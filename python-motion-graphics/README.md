# python-motion-graphics — Python だけで作るモーショングラフィックス

生成AIも動画編集ソフトも使わず、**Python のプログラムで1コマずつ絵を計算し、音楽も波の計算で作って** 15秒の MP4 にします。

- 出力：`output/motion.mp4`（1280×720 / 30fps / 450コマ / H.264 + AAC）
- テンポ：128BPM × 32拍 = ちょうど 15.0 秒
- 書き出し時間：約1分（16コアCPUで14並列、GPU不使用）

---

## 1. 必要なもの

| 種類 | 名前 | 用途 |
|---|---|---|
| Python | 3.10 以上（3.12 で確認） | 本体 |
| ライブラリ | NumPy | 画像・音を数値の配列として計算する |
| ライブラリ | OpenCV (`opencv-python`) | 図形の描画、拡大・回転・移動、フチ取り（膨張）、ぼかし |
| ライブラリ | Pillow | 文字の描画、PNG の保存 |
| 外部ツール | ffmpeg | 連番のコマと音声を MP4 にまとめる |

```
pip install numpy opencv-python pillow
```

ffmpeg がパスに無い場合は `pip install imageio-ffmpeg` を入れると、同梱の ffmpeg を自動で使います。

> **フォントについて:** `scenes.py` は Windows / macOS / Linux の代表的な太字フォントを順に探し、見つからなければ Pillow の既定フォントで描きます。好みのフォントを使うときは環境変数 `MG_FONT_TITLE`(見出し用)と `MG_FONT_MONO`(等幅用)にフォントファイルのパスを入れてください。

## 2. 使い方

```
python render.py                  # 本番：音楽を作り、450コマ描いて MP4 に書き出す
python render.py --blur 1         # 速いプレビュー（モーションブラーなし、3〜4倍ほど速い）
python render.py --still 12.5     # 12.5拍目の1枚だけ PNG で確認
python render.py --still 2 9.5 28 # 複数の拍をまとめて確認
python make_audio.py              # 音楽（output/music.wav）だけ作る
```

| オプション | 既定値 | 意味 |
|---|---|---|
| `--blur N` | 4 | モーションブラーで1コマを何回描いて平均するか。1 でブラーなし |
| `--workers N` | CPU数 − 2 | 並列で描く数 |
| `--still 拍 ...` | – | 指定した拍の静止画を `output/still_XX.XX.png` に書き出す（動画は作らない） |
| `--out パス` | `output/motion.mp4` | 出力先 |

**おすすめの調整手順：** `--still` で気になる拍を確認 → `--blur 1` で通しを確認 → 最後に本番。

## 3. ファイル構成と全体の流れ

```
common.py      テンポ・解像度・イージングの数式（映像と音の共通の物差し）
scenes.py      1コマずつ絵を計算する（5つの場面＋仕上げの効果）
make_audio.py  楽器の音を波の計算で作り、拍に合わせて並べる → music.wav
render.py      コマを並列で描き ffmpeg へ流し込み、音と合わせて MP4 に
output/        書き出し先（motion.mp4, music.wav, still_*.png）
```

```
make_audio.py ──────────────────────────────▶ music.wav ─┐
                                                          ├─▶ ffmpeg ─▶ motion.mp4
scenes.render_frame(0..449)  ×14並列 ─▶ RGBの生データ ───┘
   └ compose(拍) を4回（時間を少しずらして）描いて平均 → post（仕上げ）
```

コマは画像ファイルに保存せず、`render.py` がそのまま ffmpeg の標準入力へ流し込みます（`-f rawvideo -pix_fmt rgb24`）。

## 4. タイムライン（すべて拍番号で決まっている）

| 拍 | 秒 | 場面 | 映像 | 音 |
|---|---|---|---|---|
| 0〜8 | 0.00〜3.75 | 1 文字アニメ | MOVE（expo）/ SHAPE（back）/ RHYTHM（bounce） | キック＋裏拍ハット、文字ごとに「シュッ」 |
| 7.5〜8 | | 転換 | 斜めワイプ | 上がっていく「シュッ」 |
| 8〜16 | 3.75〜7.50 | 2 図形の変形 | 丸→四角→三角→星→丸（9・11・13・15拍目） | スネア追加、ベース開始、変形ごとに効果音 |
| 15.5〜16 | | 転換 | アイリス（円が広がる） | 上がっていく「シュッ」 |
| 16〜24 | 7.50〜11.25 | 3 3D | トンネル、ワイヤーの立方体、DEPTH | 16分のハット追加 |
| 24〜28 | 11.25〜13.13 | 4 グラフエディタ | イージング曲線と再生ヘッド、最後はブラウン管が消える演出 | 上昇音、スネアロール |
| 27.79〜28 | 0.1秒 | – | 真っ黒 | **完全な無音** |
| 28〜32 | 13.13〜15.00 | 5 フィナーレ | 爆発 → 粒子5,000個が集まって PYTHON | 爆発音、キラキラ音、決めの和音 |

グリッチは 8・12・16・20・24・28 拍目に入ります（`scenes.py` の `GLITCHES`）。

## 5. 技術的な要素

### 5.1 すべてを「拍」で決める（`common.py`）

- 1拍 = 60 / 128 = 0.46875 秒。コマ番号 `f` は `b = f / FPS / SPB` で拍番号 `b`（小数）に変換します。
- 映像は `prog(b, 開始拍, 長さ)` で 0→1 の進み具合を求め、それをイージングで曲げて位置・大きさ・角度にします。
- 音楽も `at(拍)` で拍をサンプル位置に変換して鳴らします。映像と音が同じ拍番号を見ているので、**手作業のタイミング合わせは不要**で、ずれる余地がありません。
- `beat_pulse(b)` は拍の瞬間に1へ跳ね上がって減衰する値です。文字や図形の「ドクン」とした拡大、背景の波紋、色収差の強さに使っています。

### 5.2 イージング（緩急の数式）

| 関数 | 動き | 使っている場所 |
|---|---|---|
| `ease_out_expo` | 最初速く、最後ゆっくり止まる | MOVE の滑り込み、衝撃波、トンネルの前進 |
| `ease_out_back` | 少し行き過ぎて戻る | SHAPE の出現、図形の変形、立方体の回転 |
| `ease_out_bounce` | 跳ねて止まる | RHYTHM の落下 |
| `ease_in_expo` / `ease_in_cubic` | だんだん加速 | 文字の退場、ブラウン管の潰れ |
| `ease_in_out_cubic` | ゆっくり→速く→ゆっくり | ワイプ、アイリス、粒子の集合 |

グラフエディタの場面は、この曲線そのものを見せる演出です。

### 5.3 描画とレイヤー合成（`scenes.py`）

- **キャンバス**：`float32` の (720, 1280, 3) 配列。
- **マスク方式**：図形や文字はまず白黒のマスクに描き、`comp(キャンバス, マスク, 色, 不透明度)` で `c += a × (色 − c)` として重ねます。「色」には画像も渡せるので、グラデーションで塗ったり、場面どうしを合成したりもできます。
- **なめらかな線**：OpenCV の `LINE_AA` と `shift=4`（1/16ピクセル単位の座標）を使っているので、ゆっくり動いてもガタつきません。
- **文字**：Pillow でマスク化し、`lru_cache` で使い回します。`place()` がアフィン変換（拡大・回転・移動）で画面に置きます。
- **ステッカー風のフチとずらし影**：マスクを `cv2.dilate` で太らせてフチにし、それを (10, 10) ずらして影にします。
- **3色の残像**：2・4・6コマ前の状態の位置に、ピンク・黄・水色で同じ形を塗って後ろに敷きます。止まっているときは描きません。

### 5.4 各場面の仕組み

- **図形の変形**：どの図形も「周囲を等間隔に240点、上から時計回り」に揃えています。同じ番号の点同士を補間するので、ねじれずに変形します。
- **3D**：`x/z, y/z` に焦点距離を掛ける遠近法を自前で計算しています。トンネルの輪は拍ごとに1つ分だけ前進し、奥に回り込むので切れ目なくループします。立方体は回転行列で回し、太く暗い線と細く明るい線を重ねて光って見せています。
- **粒子**：見えないところに「PYTHON」を描いて、文字の形の点を5,000個拾います。放射状に飛び散ったあと、粒子ごとに少しずつ遅れて目的地へ集まります。描画は `np.bincount` で一度に行い、膨張処理とガウスぼかしで光らせています。
- **場面転換**：斜めワイプは平行四辺形のマスク、アイリスは広がる円のマスクで、2つの場面を合成します。
- **ブラウン管が消える演出**：画面を縦に潰しながら白くし、最後に横にも潰して点にします。

### 5.5 仕上げ（`post()`）

| 効果 | やり方 |
|---|---|
| モーションブラー | 1コマを、シャッター0.5コマ分の範囲で時間をずらして4回描き、平均する |
| グリッチ | 画面を高さ6〜60pxの横の帯に切り、ランダムに左右へずらす（コマ番号を乱数の種にしているので、毎回同じ結果になる） |
| 色収差 | 赤チャンネルを右へ、青チャンネルを左へ数ピクセルずらす（拍とグリッチで強くなる） |
| 周辺の暗さ | 中心からの距離で暗くする係数を最初に1回だけ作り、毎コマ掛ける |
| フィルムの粒子 | 大きめのノイズ画像から、毎コマ違う位置を切り出して足す |
| 四隅の表示 | タイムコード・BPM・拍・場面番号を「差の絶対値」で重ねる。どの背景色の上でも読める |

### 5.6 音楽（`make_audio.py`、44.1kHz ステレオ）

| 音 | 作り方 |
|---|---|
| キック | 150Hz→46Hz へ急に下がるサイン波＋減衰。頭に雑音のクリックを付ける |
| ハット | 雑音から低い成分を削り（高域通過）、短く切る |
| スネア | 雑音＋185Hz の短い音 |
| 和音 | 音程を±16セントずつずらしたノコギリ波を7本重ね、左右に広げる。倍音の数を小節ごとに 4→18 と増やして、だんだん明るくしている |
| ベース | サイン波＋2・3倍音 |
| 「シュッ」 | 雑音を、こもった音から明るい音へ変えながら大きくし、拍の頭でスパッと切る |
| 爆発 | 長く伸びるキック＋シンバルのような雑音 |
| キラキラ | 高い音程のサイン波（金属っぽい倍音つき）を36個ランダムに散らす |

- **うねり（サイドチェイン）**：キックが鳴るたびに、和音とベースの音量を一瞬70%下げます。
- **爆発前の無音**：28拍目の直前0.1秒を完全に0にして、落差を大きくしています。
- **仕上げ**：`tanh` で軽く歪ませて音圧を整え、ピークを −0.6dBFS 付近に揃えます。最後の0.4秒でフェードアウトします。
- フィルタは移動平均だけで作っていて、SciPy は使っていません。

### 5.7 書き出しと速度

- `multiprocessing.Pool.imap` で並列に描き、コマの順番を保ったまま ffmpeg に渡します。
- ffmpeg の設定：`libx264 -crf 18 -preset medium -pix_fmt yuv420p`、`aac 192k`、`-movflags +faststart`（Web で再生しやすくする）。
- 時間がかかるのは主にフル画面の合成（`comp`）です。`--blur` の回数にほぼ比例して時間が増えます。

## 6. カスタマイズのヒント

| やりたいこと | 変更する場所 |
|---|---|
| 文字を変える | `scenes.py` の `scene_a`（MOVE など）、`scene_e` の `"PYTHON"` と `particle_setup` |
| 色を変える | `scenes.py` 冒頭の `INK` / `ORANGE` / `YELLOW` / `CYAN` / `PINK` / `VIOLET` |
| 出来事のタイミングを変える | 各 `*_state` や `prog(b, 開始拍, 長さ)` の数字。対応する音は `make_audio.py` の同じ拍番号を変える |
| テンポを変える | `common.py` の `BPM`（全体の長さも一緒に変わる） |
| 解像度・fps を変える | `common.py` の `W, H, FPS`（配置の座標は 1280×720 前提なので、あわせて調整が必要） |
| コード進行を変える | `make_audio.py` の `PROG`（MIDI番号：60 = ド） |
| 画質と速度のバランス | `--blur`（ブラーの回数）と、`render.py` の `-crf`（小さいほど高画質） |
